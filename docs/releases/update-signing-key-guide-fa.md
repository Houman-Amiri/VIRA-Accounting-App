# راهنمای ساخت و ثبت کلید امضای به‌روزرسانی — نسخهٔ ۱.۰.۱۱

این کلید تعیین می‌کند برنامهٔ نصب‌شده فقط چه بستهٔ به‌روزرسانی‌ای را بپذیرد.
**کلید خصوصی نباید در مخزن، چت یا Issue قرار بگیرد.** هرکسی که آن را داشته باشد
می‌تواند بستهٔ جعلی امضا کند.

## هفت مرحله

۱. در PowerShell روی رایانهٔ خودتان یک پوشهٔ امن برای نگه‌داری کلید بسازید:

```powershell
$keyDir = Join-Path $env:USERPROFILE "VIRA-release-key"
New-Item -ItemType Directory -Force $keyDir | Out-Null
```

۲. با پایتونِ همراهِ خود برنامه، یک جفت‌کلید Ed25519 بسازید:

```powershell
$py = "D:\3D PRINT\VIRA-Accounting\python\python.exe"
& $py "D:\3D PRINT\VIRA-Accounting\scripts\sign_update.py" keygen `
  --priv "$keyDir\update.key" --pub "$keyDir\update.pub"
```

اگر مسیر نصب شما متفاوت است، فقط همان مسیر را بگذارید. فایل `update.key`
کلید خصوصی است.

۳. از کلید خصوصی یک نسخهٔ پشتیبان در جای امن (مثلاً حافظهٔ رمزگذاری‌شده یا
پرینت در گاوصندوق) بگیرید. اگر این فایل گم شود، نسخه‌های بعدی قابل امضا و
به‌روزرسانی برای کاربران فعلی نخواهند بود.

۴. متن کلید خصوصی را در GitHub به‌عنوان Secret ثبت کنید:
`Repository → Settings → Secrets and variables → Actions → New repository secret`

- Name: `VIRA_UPDATE_SIGNING_KEY`
- Secret: محتوای کامل فایل `update.key` (از خط `-----BEGIN PRIVATE KEY-----`
  تا خط پایانی، بدون هیچ تغییر)

۵. کلید عمومی را برای تأیید نهایی نگه دارید (این یکی محرمانه نیست):

```powershell
Get-Content "$keyDir\update.pub"
```

۶. همان کلید عمومی خودکار داخل بستهٔ نصب قرار می‌گیرد: هنگام ساخت نسخه،
public key از روی Secret مشتق می‌شود، در پوشهٔ برنامه به‌صورت
`update-public-key.pem` می‌نشیند و checksum می‌شود. برنامهٔ نصب‌شده فایل
امضا (`latest.json.sig`) را الزام می‌کند.

۷. پس از ثبت Secret، یک ساخت آزمایشی (بدون tag) اجرا کنید. در لاگ مرحلهٔ
«Bake the update verification key into the payload» باید بنویسد که کلید
ساخته شد و بستهٔ ساخته‌شده شامل `update-public-key.pem` باشد. پس از آن
می‌توان نسخه را با tag منتشر کرد.

## نکات مهم

- اگر Secret ثبت نشده باشد، ساخت نسخهٔ tag دار **عمداً متوقف می‌شود**؛ این
  محافظ جلوی انتشار نسخهٔ بدون امضا را می‌گیرد.
- کاربرانی که نسخهٔ ۱.۰.۱۱ یا بالاتر را نصب کنند، دیگر به‌روزرسانیِ بدون امضای
  معتبر را نمی‌پذیرند. پس از این نسخه، هر انتشار باید با همان کلید امضا شود.
- کلید را با هیچ‌کس به اشتراک نگذارید و آن را در مخزن یا آرتیفکت‌های CI نگذارید.
