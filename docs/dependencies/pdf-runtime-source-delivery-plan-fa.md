## روش پیشنهادی؛ بدون written offer مبهم

برای کتابخانه‌های LGPL، مسیر پیشنهادی استفاده از shared-library mechanism در
LGPL 2.1 §6(b) است، مشروط به اثبات واقعیِ امکان جایگزینی نسخهٔ سازگارِ DLL و
شرایط استفادهٔ سازگار. توزیع خود کتابخانه‌ها همچنان تعهدات متن مجوز/سورس، از جمله
§4، را دارد. صرف dynamic بودن DLL مجوز توزیع خودکار نمی‌دهد.

در انتشار **بعداً و صریحاً مجازشده**، سورس و مواد کامل کنار فایل‌های باینری همان
Release عرضه شوند؛ فعلاً نوشتهٔ «در صورت درخواست سورس می‌دهیم» یا وعدهٔ سه‌سالهٔ
بررسی‌نشده جایگزین تحویل واقعی نشود. لینک باید قابل استفادهٔ دریافت‌کننده و بدون
نیاز به عضویت در Actions باشد. نام نسخه/URL واقعی اکنون عمداً تعیین نشده است.

## چک‌لیست تحویل آینده

1. **دامنهٔ دقیق:** manifest مربوط به runtime، SHA256 هر ۲۱ DLL و نگاشت هر DLL به
   بسته/سورس آن را نگه دارد؛ با SDK قبلی یا یک build جدید جابه‌جا نشود.
2. **بستهٔ سورس:** همین source ZIP با هش بالا حفظ شود؛ هر تغییر در bytes آن، هش و
   proof تازه و بازبینی مجدد می‌خواهد. extractor باید symlinkهای نسبی امن را حفظ
   کند؛ `extractall` عمومی که آن‌ها را فایل عادی می‌کند کافی نیست.
3. **ضمیمهٔ recipe کامل:** آرشیو فعلی سه wrapper واقعی را ثبت کرده است؛ اما برای
   اجرای مستقل **کل wrapper/workflow** کافی نیست. برای مثال inventory به
   `pdf_runtime_inventory.py` import دارد و build wrapper به
   `pdf_payload_smoke.ps1` رجوع می‌کند که در `vira-build/` فعلی نیستند. این کمبود
   اثبات ثبت کامل درخت سورس کتابخانه‌ها را نقض نمی‌کند؛ ولی نباید آرشیو را یک
   workflow خودبسنده یا SDK آفلاین معرفی کرد. ضمیمهٔ لازم باید recipe بومیِ قابل
   اجرا، وابستگی‌های انتقالیِ لازم، پین commit و دستور بازسازی را با هش ثبت کند.
   لازم نیست صرفاً برای ادعای تکمیل، کل برنامه را تحت یک مجوز متن‌باز قرار دهیم.
4. **حقوق ضمیمه — تأیید محدود ثبت شد:** مالک در ۲۰۲۶-۱۰-۱۸، MIT را فقط برای
   فایل‌های مشخصِ ساخت PDF تأیید کرد. [دامنه و هش‌ها](pdf-build-script-license-scope.json)،
   [متن کامل MIT](../../LICENSES/VIRA-PDF-BUILD-MIT.txt) و
   [راهنمای دامنه](../../LICENSES/README.md) باید همراه نسخه‌های مشمول باشند.
   اجازه شامل کل VIRA، backend/frontend/installer، کد upstream یا اسکریپت‌های
   نامشمولِ staging نیست. سایدکار محدود، `pdf_runtime_inventory.py` را هم دارد؛
   بنابراین این وابستگیِ import در ضمیمهٔ جدید موجود است، ولی کل workflow هنوز
   خودبسنده نیست. هش ZIP قدیمی عوض نشده و گیت کامل‌بودن recipe بسته نشده است.
5. **CRT و SDK:** نسخه و شرایط قابل اعمالِ ابزار/CRT مایکروسافت باید مستند شوند.
   static CRT بودن target یا نبودن VCRUNTIME DLL اثبات حق بازتوزیع آن کد نیست.
6. **همراه باینری:** اطلاعیه و نسخهٔ منتخب مجوزها در payload معمول/نصب‌شده و
   بستهٔ update قابل دسترس باشند؛ متن‌های کپی‌شدهٔ GPL جایگزینِ انتخاب‌نشده نباید
   به‌اشتباه به معنای GPL کردن کل برنامه معرفی شوند. اعتبار FTL برای FreeType و
   notices اجزای جانبی آن جدا حفظ شوند.
7. **جایگزینی LGPL:** نامزد واقعاً نصب‌شده در مسیر فارسی/فاصله‌دار باید DLL سازگارِ
   جایگزین‌شده را بارگذاری کند. EULA یا گیت hash/signature نباید عملاً این حق یا
   reverse engineering برای اشکال‌زدایی تغییرات کتابخانه را ممنوع کند. این تست
   هنوز انجام نشده است؛ proof قبلی فقط مبدأ private DLLهای اصلی را ثابت می‌کند.
8. **هم‌مکانی و دسترسی:** source ZIP، ضمیمهٔ recipe دارای حقوق مشخص، notices و
   SHA256SUMS کنار assets همان Release قرار گیرند؛ دانلود ناشناس، اندازه و هش
   واقعی پس از آپلود کنترل شوند. URL نباید artifact موقت Actions یا لینک امضاشدهٔ
   منقضی‌شونده باشد. فعلاً هیچ URL عمومیِ تحویل سورس برای این نامزد ثبت نشده است.
9. **delta:** اگر native تغییر کرد، نسخهٔ جدید باید به سورس متناظرِ همان native
   متصل باشد؛ اگر native تغییر نکرد، ارجاع به سورس عمومیِ ثابتِ قبلی می‌تواند
   حفظ شود. update روتین نباید بهانه‌ای برای دانلود مجدد کل setup باشد. تست
   تغییر native، جایگزینی، شکست عمدی و rollback فایل‌ها/DB جدا لازم است؛ موفقیت
   rollback عمومیِ فعلی این سناریوی جدید را خودبه‌خود ثابت نمی‌کند.
10. **بستن گیت:** فقط بعد از تکمیل بازبینی اجزا، حقوق CRT/recipe، تحویل واقعی سورس،
    قابلیت جایگزینی کتابخانه و bootstrap/update، نامزد می‌تواند برای ادغام عادی
    ارزیابی شود. آزمون کسب‌وکار روی نصب کاربر طبق درخواست او به بعد موکول است؛
    نه حذف شده و نه خودکار تأیید شده است.

## اعمال تأیید MIT بدون بازسازی native

`python scripts/check_pdf_build_license.py` دامنهٔ دقیق ۹ فایل، بایت‌های مجوز،
هش محتوای مرجع و محدودبودن تأیید به ابزار ساخت را کنترل می‌کند. گزینهٔ
`--sidecar <new-directory>` تنها همان فایل‌ها، متن MIT، manifest دامنه و README
را کپی می‌کند؛ فایل برنامه، DLL، داده یا ابزار کامپایل به آن اضافه نمی‌شود و
مسیر موجود بازنویسی نمی‌شود. workflow بررسی مجوز این ضمیمه را کنار source ZIP
اصلی قرار می‌دهد. هفت فایل تاریخیِ آرشیو با نسخهٔ مرجع مجوز، پس از نرمال‌سازی
صرفاً CRLF/LF، یکسان‌اند؛ دو فایل دیگر helper/checker در سایدکار ارائه می‌شوند.
وضعیت BLOCKED یک تصمیم آمادگی انتشار این پروژه است، نه محدودیت اضافه بر MIT.

اجرای موفقِ بعد از تأیید مالک و artifact دارای ضمیمهٔ MIT در
[proof مجوز اسکریپت‌ها](pdf-build-script-license-proof.json) ثبت شده است؛ پین قدیمیِ
ممیزیِ مواد بالا به اجرای پیش از اعطای MIT اشاره می‌کند و به‌عنوان سابقه حفظ شده است.

## به‌روزرسانی اجرایی: بستهٔ بررسی واقعی و استخراج امن (۲۰۲۶-۱۰-۱۸)

بخش‌های ۹فایلی بالا سابقهٔ تأیید اولیه‌اند؛ دامنهٔ **فعلی ۱۲ فایل صریح** است:
ورودی native و بازرس آن، و اکنون `pdf_source_kit.py` به‌عنوان مشتقات ابزار ساخت.
مجوز کل برنامه یا کد CRT تغییر نکرده است. برای ورودی مستقل، از راهنمای جدید و
`rebuild_pdf_native.ps1` استفاده شود، نه wrapper قدیمیِ وابسته به app/staging.

`pdf_source_kit.py --archive <original-zip> --out <new-directory>` اکنون بستهٔ بررسی
را واقعاً می‌سازد: ZIP اصلیِ بدون تغییر، سایدکار مجاز، مجوز/دامنه، دستور ساخت،
notices/مکمل‌ها، inventory/policy/review و مرجع رسمی CRT، با manifest اندازه/SHA256.
`--verify` فقط کتابخانهٔ استاندارد Python می‌خواهد؛ کد checker از پوشهٔ هدف را
اجرا نمی‌کند. digest مستقل و verifier مورد اعتماد شرط authentication‌اند؛ هش‌های
خود بسته به‌تنهایی هویت ناشر نیستند. `--extract-sources` مسیر تازه می‌خواهد و
symlinkهای نسبی امن و executable bit را حفظ می‌کند؛ escape/collision/cycle،
symlink/junction خروجی از envelope، special file و بازنویسی مسیر موجود رد می‌شوند.
نبود مجوز ساخت symlink در ویندوز، خطای صریح است، نه flatten کردن لینک.

[proof بسته](pdf-source-kit-proof.json) و [گزارش](../reports/pdf-source-kit-and-crt-probe-fa.md)
اجرای واقعی استاندارد-library/`-I -S`، استخراج ۲۱ symlink و محاسبهٔ مجدد و برابرِ
درخت هر ۲۰ بسته / ۲۵٬۵۰۵ ورودی را ثبت می‌کنند. source ZIP همان هش قبلی را دارد.
این **artifact بررسی ۹۰روزه** است؛ انتشار عمومی/ناشناسِ پایدار اجرا نشده است.

همچنان خودِ فرمان build، منابع پین‌شده را از شبکه می‌گیرد؛ مصرف مستقیم درخت‌های
local استخراج‌شده/تغییرکرده یا بازسازی آفلاین ثابت نشده و overlay بررسی‌شده لازم
است. بستهٔ بررسی را نباید اثبات خودکار همهٔ گیت‌های source delivery نامید.
[probe CRT](pdf-crt-static-probe-proof.json) نیز فقط یک برنامهٔ جدا با `/MT` است،
نه map اجزای همان ۲۱ DLL یا اجازهٔ توزیع. entitlement و شروط CRT/SDK، LGPL/EULA،
bootstrap/native delta/rollback و پذیرش نصب‌شده همچنان مستقل و بازند.

## به‌روزرسانی بعدی: مصرف واقعی سورس محلی (۲۰۲۶-۱۰-۱۸)

بخش ۱۲فایلی بالا سابقهٔ مرحلهٔ قبل است؛ اکنون دامنهٔ صریح **۱۴ فایل** شامل
`prepare_pdf_local_sources.py` و پین‌های recipe است. مسیر محلیِ جداگانه با گزینهٔ
موجود `-OverlayPorts`، archive/kit احراز‌شده و preferred source استخراج‌شده کار
می‌کند؛ فرمان پیش‌فرض driver همچنان target source دانلود می‌کند.

[proof واقعی](pdf-local-source-replay-proof.json) و
[گزارش فارسی](../reports/pdf-local-preferred-source-replay-fa.md): ساخت ویندوز
`39146630126 / 576c0ea` و ممیزی ۲۰ درخت/۲۱ DLL موفق شد و تابع واقعی Pango مقدار
تغییرکردهٔ `1.58.0-vira-local-source` داد. فقط Pango با مرجع اصلی اختلاف دارد؛
۱۹ درخت دیگر (شامل alias خالی) برابرند و ورودی بیرونی پس از build همان محتوا را
دارد. ساخت compiler/bootstrap/ابزار host هنوز ممکن است شبکه بخواهد؛ SDK آفلاین
یا bitwise reproducibility ثابت نشده است.

شکست واقعی لینک نسبی ویندوز و make/gettext حفظ شدند؛ استخراج امن اکنون جداکنندهٔ
native لینک و زمان محلی ثبت‌شدهٔ ZIP را حفظ می‌کند. ترتیب mtime برای جلوگیری از
regeneration ناخواستهٔ Autotools ضروری بود. خروجی تو‌در‌تو درون kit/ورودی نیز
پیش از ایجاد رد می‌شود. دستور دقیق و محدودیت PCRE2/SLJIT/APNG در راهنمای همراه‌اند.

ZIP قدیمی **دست‌نخورده** ماند. مرجع build تغییرکرده جداست و `source_archive=null`
دارد؛ metadata قدیمی صرفاً provenance است، نه سورس متناظر کاملِ DLL اصلاح‌شده.
این آزمایش خصوصی نامزد runtime عادیِ توزیع نیست و آرشیو متناظر جدیدی برای آن
آماده/منتشر نشده است. برای هر عرضهٔ بعداً مجازشده، سورس کامل نسخهٔ واقعی، recipe،
اعلان تغییر/تاریخ لازم و notices همراه باینری همان نسخه باید آماده و تحویل شوند.

تمام شش گیت همچنان بازند، از جمله source delivery عمومی/پایدار، recipe آمادهٔ
دریافت‌کننده، بازبینی اجزا و حق/نگاشت CRT همان DLLها، LGPL/EULA در نصب واقعی و
bootstrap/native delta/rollback/پذیرش. artifact نودروزه و proof فنی جای آن‌ها نیستند؛
مجوز کل app، نسخه/تگ/Release، payload نصب، داده و محاسبات تغییر نکردند.
