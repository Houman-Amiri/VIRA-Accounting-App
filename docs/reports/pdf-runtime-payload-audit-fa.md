# ممیزی runtime و آزمون بستهٔ خصوصی PDF — بدون انتشار

تاریخ: ۲۰۲۶-۱۰-۱۷

## هدف و مرز

ادامهٔ گام قبلی برای نزدیک‌کردن آزمون بومی PDF به چیدمان نصب واقعی، بدون نصب
سراسری GTK، دست‌زدن به DB کاربر، ساخت نسخهٔ عمومی یا فرض پذیرش نصب نهایی.

**نتیجهٔ قطعی گام فنی:** بستهٔ خصوصی با CPython همراه و closure ممیزی‌شده روی
Windows موفق شد؛ **هر پنج job CI موفق‌اند**. این نتیجه **آمادگی انتشار runtime نیست**.

- کد تأییدشده: `d848a08314cbf50445978e84e724dacdd26cec17`
- [CI نهایی 39038459962](https://github.com/Houman-Amiri/VIRA-Accounting-App/actions/runs/39038459962)
- [artifact PDF و ممیزی، بدون DLL یا Python](https://github.com/Houman-Amiri/VIRA-Accounting-App/actions/runs/39038459962/artifacts/12102754567)
- [فهرست ثابت ۲۷ DLL با هش و وابستگی‌ها](../dependencies/pdf-runtime-win64-inventory.json)
- انتشار `39038460021`، Skipped؛ هیچ تگ یا نسخهٔ عمومی جدید ایجاد نشده است.

مجوز و corresponding source گیت مستقل‌اند. نامزد خصوصی از ابتدا با وضعیت
`BLOCKED_PENDING_LICENSE_AND_CORRESPONDING_SOURCE_REVIEW` و فایل `DO_NOT_DISTRIBUTE.txt`
نشانه‌گذاری می‌شود؛ **موفقیت فنی مجوز بازتوزیع نیست**. DLLها وارد مخزن یا artifact
عمومی نمی‌شوند و هنوز به مسیر عادی تولید نصب/دلتا افزوده نشده‌اند.

## تغییرات فنی

1. `scripts/pdf_runtime_inventory.py` آرشیو رسمی WeasyPrint 70.0 را با همان SHA256
   پین‌شدهٔ گام قبلی می‌پذیرد؛ کتابخانه‌ها را بدون اجرا به‌صورت PE بررسی می‌کند.
   import مستقیم/تأخیری، معماری AMD64، اندازه، SHA256 و اطلاعات نسخهٔ موجود در PE
   ثبت می‌شوند. شش ریشهٔ صریح Pango/PangoFT2/GObject/HarfBuzz/Subset/Fontconfig و
   وابستگی‌هایشان انتخاب می‌شوند؛ Python 3.14/پلاگین‌ها/کتابخانه‌های نامرتبط upstream
   همراه نامزد کپی نمی‌شوند.
2. حل وابستگی فقط در همان آرشیو انجام می‌شود؛ هیچ کتابخانهٔ مفقودی از PATH یا
   MSYS/GTK نصب‌شده قرض گرفته نمی‌شود. فقط DLLهای صریحاً جزء Windows 10+ و API-setها
   وابستگی سیستمی‌اند؛ MSVCP، VCRUNTIME، libgcc و libstdc++ «جزء تضمین‌شدهٔ ویندوز»
   فرض نمی‌شوند. وابستگی مفقود، نام مسیر ناامن، تداخل حروف کوچک/بزرگ، DLL معماری
   اشتباه یا اتصال به ABI پایتون upstream باعث شکست گیت می‌شوند.
3. stage تولید موجود، CPython مدیریتشدهٔ واقعی را با `--system --managed-python`
   انتخاب می‌کند، نه Python محیط مجازی. شکست نصب/کشف Python، export قفل وابستگی،
   نصب site-packages یا ساخت manifest دیگر نمی‌تواند با فرمان بعدی پنهان شود.
4. فقط در CI، همین `stage_app_payload.ps1` با نسخهٔ خصوصی
   `0.0.0-private-pdf-proof` اجرا می‌شود؛ کل بسته به مسیر دارای فاصله و حروف فارسی
   منتقل می‌شود. نامزد runtime **بعد از stage تولید و فقط برای آزمون خصوصی** اضافه
   می‌شود. این مسیر جدید تولید عمومی محسوب نمی‌شود.
5. worker با `python.exe -I` از همان بسته اجرا می‌شود؛ نسخهٔ ۳٫۱۱، مسیر executable و
   base_prefix، نبود مسیر venv و نبود `pypdf`/`pefile` در وابستگی تولید کنترل می‌شود.
   DLLها داخل نامزد خصوصی‌اند؛ فونت سیستم تنظیم نشده است. به علت محدودیت upstream
   در خواندن متغیر محیطی مسیر فارسی، تنظیم/cache خالی Fontconfig فعلاً در پوشهٔ
   موقت ASCII همان اجرای خصوصی است؛ رفع عمومی این محدودیت هنوز گیت باز است.
   همهٔ ریشه‌ها و سایر وابستگی‌های واقعاً بارگذاری‌شده باید از پوشهٔ خود نامزد باشند.
6. PDF کوتاه و ۱۰۰ ردیفی با سرویس واقعی اپ ساخته می‌شوند. بازرسی PDF جداگانه در
   محیط توسعه انجام می‌شود: A4، چندصفحه‌ای شدن، TTF واقعی Regular/Bold و هر ۳۰ رقم
   مصرف‌شده در هر وزن. فایل‌های اصلی payload همچنان با manifest قبلی تطبیق داده
   می‌شوند؛ تنها cache پایتون از مقایسهٔ پس از اجرا مستثناست.
7. artifact جدید فقط PDF ساختگی و JSON ممیزی/اثبات است؛ app، Python و DLLها آپلود
   نمی‌شوند. ابزارهای بازرسی صرفاً dev هستند.

## شواهد نهایی

- ۱۹ تست جدید ممیزی و کنترل‌های منفی موفق؛ مجموع بک‌اند **۳۸۷ موفق**.
- **۱۹۶ تست فرانت‌اند** محلی و **شش سناریوی مرورگر واقعی** در CI موفق‌اند.
  Ruff، Mypy برای ۸۴ فایل، Bandit، TypeScript، ESLint، Prettier، قرارداد OpenAPI
  و build موفق‌اند. کنترل‌های mock/گراف ساختگی مدرک اجرای بومی نیستند.
- CPython خصوصی واقعاً **۳٫۱۱٫۱۷ / AMD64** بود؛ `-I`، executable و base_prefix
  داخل بسته، نبود pypdf/pefile توسعه و callbackهای integer/float تأیید شدند.
- **۲۷ DLL، جمعاً ۱۵٬۵۳۴٬۱۴۲ بایت** در closure انتخاب و هر ۲۷ مورد از مسیر خود
  نامزد بارگذاری شدند؛ **۵۱ DLL نامرتبط upstream حذف** شدند. شش ریشه و importهای
  مستقیم/تأخیری حل شدند. هیچ DLL از نصب GTK/MSYS یا libffi متفاوت Python قرض گرفته نشد.
- PDF کوتاه: **۱ صفحه A4 / ۲۱٬۴۶۳ بایت**؛ سند ۱۰۰ ردیفی: **۴ صفحه A4 / ۳۲٬۹۷۳ بایت**.
  در هر دو، TTFهای واقعی وزیرمتن Regular/Bold و هر ۳۰ رقم مصرف‌شده در هر وزن تأیید شدند.
  SHA256 خروجی‌ها با گام مستقل قبلی برابر بود:
  - کوتاه: `ae92659254d59fed845c8ce4880d7bfa2846d64850085e5facfc657579ee4ebd`
  - بلند: `8273a9acad1e600661ec44a7ff4d2d1ae6e8fba69914a5b1c2aa0344871c5650`
- manifest فایل‌های تولیدِ stageشده، جز cache پایتون، بعد از آزمون بدون تغییر ماند.
  گیت‌های قبلی API بومی، delta/rollback و مهاجرت واقعی از ۱.۰.۱۰ با helper کامپایل‌شده
  نیز در همین CI موفق‌اند؛ آن‌ها جای گیتِ آیندهٔ ارتقای runtime توزیع‌شده را نمی‌گیرند.
- ۱۶ DLL حتی FileVersion ندارند؛ نسخهٔ PE بقیه نیز لزوماً نسخهٔ upstream سورس نیست
  (مثلاً رشتهٔ ۱٫۰ برای libintl). **هر ۲۷ مورد از نظر مجوز/سورس UNREVIEWED مانده‌اند**.
  JSON ثابت فقط شواهد باینری و آغاز بررسی منشأ است، نه تأیید حقوقی یا SBOM کامل.

## مشکلات کشف‌شده در گیت جدید

- اجرای اولیهٔ خصوصی در CI شکست خورد؛ Python با `ctypes`، فایل هم‌نام `libffi-8.dll`
  خودش را بارگذاری کرده بود، نه نسخهٔ ممیزی‌شدهٔ runtime. گیت مسیر DLL این اختلاف
  را کشف کرد؛ اجازهٔ استفادهٔ پنهان از فایل دیگر داده نشد. نامزد خصوصی پیش از import
  ctypes/WeasyPrint، libffi ممیزی‌شده را با CFFI بارگذاری می‌کند و callbackهای عدد
  صحیح و اعشاری ctypes را نیز می‌آزماید. این ترتیب باید بعداً در bootstrap واقعی
  و نه صرفاً worker خصوصی پیاده و آزموده شود.
- Fontconfig upstream مسیر `FONTCONFIG_FILE` حاوی حروف فارسی را در CRT به `?`
  تبدیل می‌کرد. PDF از `@font-face` ساخته شده بود، اما این خطا قبولی تنظیم مستقل
  از فونت سیستم نبود. آزمون خصوصی تنظیم خالی را به پوشهٔ موقت ASCII منتقل می‌کند؛
  مسیر خود app، DLLها، interpreter و فونت‌های اپ همچنان حاوی فاصله/فارسی است.
  این workaround خصوصی، پشتیبانی عمومی از همهٔ مسیرهای Unicode محسوب نمی‌شود.

## گیت‌های باز

- ثبت و بررسی نسخهٔ دقیق، متن مجوز، patchها و corresponding source **هر وابستگی**.
  رشتهٔ نسخهٔ PE به‌تنهایی منشأ قابل‌اثبات سورس/ساخت نیست. مجوز خود WeasyPrint نیز
  مجوز همهٔ DLLهای بومی را پوشش نمی‌دهد. ممیزی فعلی مجوز حقوقی صادر نمی‌کند.
- importهای PE همهٔ LoadLibraryهای پویا/پلاگین‌های احتمالی را نشان نمی‌دهند؛ آزمون
  واقعی PDF شاهد تکمیلی برای قالب فعلی است، نه پوشش همهٔ قالب‌ها/تصاویر آینده.
- bootstrap عمومی باید تقدم بارگذاری libffi و تنظیم Fontconfig را برای مسیرهای
  Unicode عمومی حل کند؛ workaround موقت ASCII فقط متعلق به آزمون خصوصی است.
- پس از تکمیل مواد مجوز/سورس: ادغام runtime تأییدشده در stage عادی تولید، راه‌انداز
  بدون env دستی، manifest/delta و آزمون نصب/ارتقا/rollback همان runtime.
- بازبینی انسانی RTL و چاپ، پذیرش کسب‌وکاری با دادهٔ واقعی و تأیید نصب کاربر طبق
  خواست قبلی همچنان برای انتهای کار می‌مانند. هیچ فرمول، مقدار مالی، DB/schema،
  نسخهٔ عمومی یا تگی تغییر نکرده و خروجی مستقل Word وعده داده نشده است.
