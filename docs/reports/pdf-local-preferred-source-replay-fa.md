# ساخت native PDF از سورس محلیِ داخل بسته

تاریخ: ۲۰۲۶-۱۰-۱۸. دامنهٔ این مرحله فقط **اثبات فنیِ مصرف سورس محلی** است؛
نه نصب روی سیستم کاربر، انتشار، مجوز کل برنامه یا تأیید حقوقی موتور.

**DoD فنی این مرحله پاس شد:** ساخت و ممیزی واقعی ویندوز
[39146630126 / 576c0ea](https://github.com/Houman-Amiri/VIRA-Accounting-App/actions/runs/39146630126)
موفق شد. این نتیجه جای شش گیت توزیع/نصب را نمی‌گیرد.

## چه چیزی تغییر کرد؟

فرمان پیش‌فرض `rebuild_pdf_native.ps1` همچنان از شبکه سورس upstream می‌گیرد.
برای مصرف درخت‌های پچ‌شدهٔ واقعاً ثبت‌شده در source kit، مسیر جداگانهٔ
`scripts/prepare_pdf_local_sources.py` و تنظیمات صریح
`docs/dependencies/pdf-local-source-port-pins.json` اضافه شد. خود driver و پروفایل
native نسبت به اثبات مستقل قبلی تغییر نکردند؛ فقط گزینهٔ موجود `-OverlayPorts`
به overlay تولیدشده اشاره می‌کند. [دستور دقیق](../dependencies/pdf-native-rebuild-guide.md).

خروجی catalog واقعیِ آرشیو اصلی، نه حدس از upstream، نشان داد که ۱۹ بسته هرکدام
یک ریشهٔ سورس دارند و `pthread` فقط یک واسط خالی است. نام/هش recipe و تعداد دقیق
فراخوانی‌های دریافت سورس پین شده‌اند. چندریشه‌ای یا نام ریشهٔ غیرمنتظره **رد می‌شود**؛
ابزار بی‌صدا یکی از ریشه‌ها را انتخاب نمی‌کند.

ابزار فقط با Python استاندارد و `-I -S` اجرا می‌شود. digest مستقل manifest و
verifier مورد اعتماد لازم‌اند؛ خودسازگاری یک بسته، هویت ناشر نیست. kit، ZIP اصلی،
درخت فایل/لینک و recipeها پیش از ساخت overlay کنترل می‌شوند. خروجی باید جدید باشد؛
هیچ پوشهٔ نصب، پایگاه داده یا درخت ورودی بازنویسی/پاک نمی‌شود. خروجی استخراج
باید بیرون kit و خروجی overlay باید بیرون kit/درخت ورودی باشد؛ قرار دادن خروجیِ
تازه درون ورودی هم پیش از ایجاد آن رد می‌شود، نه فقط بازنویسی مسیر موجود.

برای target ثابت `x64-vira-pdf`، دریافت/استخراج/پچ دوبارهٔ upstream با کپی درخت
محلیِ ازقبل‌پچ‌شده به `buildtrees/<port>/src` در **محل build تازه** جایگزین می‌شود.
recipe اصلی و مجوز upstream کنار مشتق حفظ می‌شوند؛ متن کامل MIT هم همراه overlay
است. مسیر host از recipe اصلی استفاده می‌کند و توابع دانلود به‌طور سراسری override
نمی‌شوند. کامپایلر، bootstrap، Python/Meson/MSYS و ابزارهای host هنوز ممکن است
دانلود شوند؛ این **SDK آفلاین یا تضمین بازتولید بیت‌به‌بیت نیست**.

- PCRE2: SLJIT داخل سورس ثبت‌شده قبلاً ادغام شده؛ حذف/ادغام مجدد آن نیز حذف شد.
- libpng: feature اختیاری APNG در این capture فعال نبوده؛ فعال‌کردن آن خطای صریح
  می‌دهد، نه ادامه با patch گمشده. variant جدید بازبینی جدا می‌خواهد.
- لینک‌های نسبی امن حفظ می‌شوند؛ لینک خارج/گمشده/پوشه‌ای و junction و مسیر دارای
  متن تزریق‌پذیر CMake پذیرفته نمی‌شوند. نبود مجوز ساخت symlink در ویندوز خطاست.
- بعد از کامپایل، هش درخت ورودی دوباره کنترل می‌شود تا build ورودی بیرونی را
  تغییر نداده باشد؛ ممیزی جداگانه خودِ درخت واقعی build را نیز کنترل می‌کند.

## اثبات اجراشده: تغییر واقعیِ Pango، نه فقط تولید فایل تنظیمات

CI از ZIP اصلیِ دست‌نخورده، kit محدود را می‌سازد و با digest مستقل استخراج می‌کند.
سپس در کپی محلی `pango/pango-utils.c` فقط return تابع `pango_version_string()`
به `PANGO_VERSION_STRING "-vira-local-source"` تغییر می‌کند. فایل کامل تغییرکرده،
بایت‌های قبل/بعد، SHA256 قبل/بعد و هش درخت‌ها در شواهد خصوصی نگهداری می‌شوند.
بدون `--allow-modified` چنین اختلافی پذیرفته نمی‌شود.

آزمون پایان، هم‌زمان این موارد را واقعاً ثابت کرد:

1. ساخت مستقل همهٔ بسته‌های target، بدون backend/frontend/uv/Node یا کش باینری؛
2. ۲۰ درخت مطابق ورودی آماده‌شده: ۱۹ برابر مرجع اصلی (شامل alias خالی) و یک Pango
   با تغییر صریح؛ صرف وجود فایل خروجی کافی نیست؛
3. closure/مالک و بارگذاری واقعی ۲۱ DLL از پوشهٔ build خصوصی؛
4. فراخوانی DLL واقعی و دریافت دقیق `1.58.0-vira-local-source`؛
5. ثابت‌ماندن درخت ورودی بیرونی و ZIP اصلی و عدم افزودن DLL به نصب/Release.

مرجع `local-source-reference.json` **مجزا** است: آرشیو قدیمی را فقط در
`original_source_archive` نگه می‌دارد و `source_archive` را null می‌کند. این آزمایش
نمی‌گوید ZIP اصلیِ بدون تغییر سورس متناظر کامل DLL تغییرکرده است. بستهٔ سورس
متناظر جدید و شرایط/اعلان‌های لازمِ تحویل نسخهٔ اصلاح‌شده هنوز آماده/منتشر نشده‌اند؛
این تغییر خصوصی نامزد runtime معمول نصب‌شده نیست.

## شکست واقعی ویندوز و اصلاح آن

اجرای اول `39143696133 / ebf3015` در آماده‌سازی شکست خورد؛ به علت دسترسی‌ناپذیری
log سرویس Actions در sandbox، diagnostic محدود و صریح به annotation اضافه شد،
بدون حذف کنترل. اجرای `39143878456 / ce49a74` وجود لینک گمشده/پوشه‌ای را نشان داد.
آرشیو اصلی فقط لینک فایلِ نسبی امن دارد؛ در ویندوز، target نسبیِ reparse point با
جداکنندهٔ POSIX می‌تواند ساخته شود اما resolve نشود. استخراج‌کننده اکنون جداکنندهٔ
native ویندوز را هنگام **ایجاد** لینک به کار می‌برد؛ متن لینک برای digest همچنان
به `/` نرمال می‌شود. لینک flatten یا شرط سلامت آن ضعیف نشده است.

تست استخراج واقعی، لینکِ دارای زیرپوشه را پوشش می‌دهد؛ تست مصنوعی مستقل نیز
ارسال `sub\\file` به API ویندوز را کنترل می‌کند. `b345a25` اصلاح را ثبت کرده و
`1fe9a13` متن کامل MIT را نیز کنار overlay تولیدشده حفظ می‌کند. بررسی مرز خروجی
در `0e409dd` تقویت شد: مسیر جدیدِ تو‌در‌تو در kit یا درخت ورودی نیز رد می‌شود تا
ابزار با افزودن فایل تازه، manifest یا ورودی خودش را خراب نکند. سه تست رگرسیون
جدا، رد این حالت‌ها پیش از ایجاد خروجی/بازرسی ورودی را کنترل می‌کنند.

## شکست Autotools و حفظ زمان فایل‌ها

اجرای `39144188922 / 1fe9a13` از آماده‌سازی عبور کرد، اما کامپایل target
`gettext-libintl` شکست خورد. diagnostic کوتاهِ نخست، پیام‌های تکراری libtool با
`-nologo` را نشان می‌داد؛ بررسی کامل‌ترِ artifact با اجرای جداگانهٔ
`39146694091 / ca4b61e` خطای توقف make را نیز بازیابی کرد:
`No rule to make target '../config.h', needed by 'bindtextdom.lo'`.
[شواهد کامل بازیابی‌شده](../dependencies/pdf-local-source-replay-failure-evidence.json)
شامل tail ثبت‌شده، آخرین ۲۵۰ خط build و timestampهای واقعی ZIP است؛ هش فایل در
proof نهایی ثبت می‌شود. diagnostic خوانده شده است، نه حدس از یک پیام کوتاه.

استخراج قبلی فقط محتوا/لینک/حالت اسکریپت را حفظ می‌کرد، نه mtime. زمان تازهٔ
ترتیب استخراج، مثلاً `intl/configure.ac` را از `intl/configure` جدیدتر می‌کرد؛
در ZIP واقعی اولی `2024-02-21 16:31:48` و دومی `16:35:54` است. برای Autotools
این ترتیب معنی دارد و می‌تواند regeneration ناخواسته و بازنویسی Makefileهای
اصلاح‌شدهٔ recipe را راه بیندازد. `576c0ea` اکنون زمان ثبت‌شدهٔ هر فایل عادی را
با دقت/زمان محلیِ خود ZIP بازمی‌گرداند، پیش از تنظیم mode؛ بایت‌های ZIP/سورس و
الگوریتم digest عوض نشده‌اند. این کار ادعای timestamp مطلق UTC یا بازتولید
بیت‌به‌بیت نیست. تست مستقل، ترتیب configure/configure.ac و ثبات محتوا را کنترل
می‌کند. build تازه با این اصلاح تا پایان کامپایل و ممیزی موفق شد؛ این موفقیت،
حفظ ترتیب mtime را در این مسیر تأیید می‌کند، نه ریشه‌یابی مستقل و قطعیِ تک‌تک
پیام‌های libtool. گیت هش/سلامت یا patch تولید Makefile حذف/ضعیف نشد.

## مرزهای باقی‌مانده

تمام شش گیت توزیع همچنان بازند: بازبینی کامل حقوق اجزا، حق و نگاشت CRT واقعیِ
DLLها، recipe/تحویل آمادهٔ دریافت‌کننده، تحویل عمومی پایدارِ source، جایگزینی
LGPL/EULA در **نصب واقعی** و bootstrap/update/rollback native و پذیرش کسب‌وکار.
probe جداگانهٔ CRT قبلی مجوز همین DLLها نیست؛ اجرای تابع Pango تغییرکرده نیز
تأیید حق جایگزینی در برنامهٔ نصب‌شده یا سازگاری EULA نیست.

وضعیت runtime همچنان `BLOCKED_PENDING_LICENSE_AND_CORRESPONDING_SOURCE_REVIEW`.
دامنهٔ MIT فقط **۱۴ فایل صریح ابزار/تنظیمات ساخت** است، نه app/upstream/CRT.
نسخه، تگ، Release، installer، payload معمول، محاسبات/اعداد و دادهٔ کاربر عوض نشده‌اند.
تست کسب‌وکارِ نصب طبق درخواست کاربر همچنان به بعد موکول است، نه پذیرفته‌شده.
