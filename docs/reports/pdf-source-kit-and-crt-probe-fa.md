# بستهٔ بررسی سورس و آزمون جداگانهٔ CRT

تاریخ: ۲۰۲۶-۱۰-۱۸. این ادامهٔ آماده‌سازی است؛ **نه انتشار، نصب یا مجوز توزیع**.

## بستهٔ واقعی به‌جای چک‌لیست صرف

ابزار جدید `scripts/pdf_source_kit.py` فقط با کتابخانهٔ استاندارد Python، در یک
مسیر جدید این مجموعه را می‌سازد: source ZIP اصلیِ بدون تغییر، سایدکار فایل‌های
ساخت دارای MIT، متن مجوز/دامنه، راهنمای ساخت مستقل، inventory، policy/review و
notices/مکمل‌ها، مرجع شرایط رسمی CRT، README و manifest اندازه/SHA256 هر فایل.
۲۴ فایل در manifest، به‌علاوهٔ خود manifest، ثبت می‌شوند؛ دامنهٔ کد ساخت با افزودن
صریح همین مشتق ابزار ساخت، **۱۲ فایل** است؛ نه مجوز کل برنامه یا مجوز کد CRT.

ساخت/بازرسی، سورس پین‌شده و درخت هر بسته، ارتباط notices و policy و شش گیت اجباری
را کنترل می‌کند. فایل اضافه، حذف یا تغییر، متن مکملِ ناسازگار با source ZIP،
دامنهٔ گسترده و مسیر موجود رد می‌شوند. بررسی یک پوشهٔ دلخواه، checker داخل آن
پوشه را **اجرا نمی‌کند**؛ فقط checker کنار خودِ بازرسِ مورد اعتماد به کار می‌رود.
لود checker نباید cache جدید به بستهٔ صرفاً خواندنی اضافه کند.

هش‌های داخل بسته به‌تنهایی هویت ناشر را اثبات نمی‌کنند. دریافت‌کننده به digest
مستقل و مورد اعتماد و خودِ verifier مورد اعتماد نیاز دارد؛ «خودش خودش را تأیید
می‌کند» امضای دیجیتال یا authentication نیست. گزینهٔ هش مستقل، پیش از بررسی
بقیهٔ envelope کنترل می‌شود. حتی دریافت از artifact Actions، تحویل پایدار عمومی
به دریافت‌کننده محسوب نمی‌شود.

## اثبات واقعی بسته و استخراج

اجرای موفق [39112775358](https://github.com/Houman-Amiri/VIRA-Accounting-App/actions/runs/39112775358)
روی `b9dc528` بدون نصب وابستگی‌های app، بسته را ساخت. سپس فرمان داخل خود سایدکار
با **`python -I -S`** و هش مستقل manifest اجرا شد؛ استخراج واقعی صورت گرفت و بعد
دوباره از روی فایل‌های استخراج‌شده هش درخت‌های هر **۲۰ بسته / ۲۵٬۵۰۵ ورودی /
۲۱ symlink** محاسبه و با مرجع برابر شد. اجرای دومِ read-only هم موفق بود.

[پین اجرا، هش manifest و artifact](../dependencies/pdf-source-kit-proof.json).
این شواهد از annotation کامل CI و مشخصات artifact گرفته شده است؛ ادعای دانلود
مجدد همهٔ bytes artifact توسط sandbox نیست. هش ZIP اصلی همچنان
`259532d2cd8c5d3b176402acdcfb9daadb2cb897d5710010cc198eeabe5401de` است.
artifact بررسی ۹۰روزه فاقد payload جدید DLL/EXE نصب‌شدنی است؛ فقط source ZIP
قبلی و مواد همراه را دارد. حفظ دادهٔ باینری احتمالیِ fixtureهای upstream در سورس
اصلی، نباید با افزودن موتور باینری جدید به نصب اشتباه گرفته شود.

استخراج‌کننده `extractall` نیست: مسیر مطلق/`..`/drive/backslash/NUL، نام‌های
نامعتبر قابل‌حمل ویندوز، collision نام/فایل/پوشه، special file، لینک خارج از بسته،
لینک گمشده/چرخه‌ای و عبور از والد symlink رد می‌شوند؛ حجم/تعداد ورودی محدود است.
فایل‌ها پیش از لینک‌ها نوشته می‌شوند و executable bit اسکریپت حفظ می‌شود، نه
setuid/setgid. مسیر خروجی باید جدید باشد. در ویندوز، مجوز ساخت symlink لازم است؛
نبود آن خطای صریح می‌دهد، نه تبدیل پنهان لینک به فایل معمولی. خروجی ناقصِ شکست
برای بررسی باقی می‌ماند و مسیر قدیمی پاک/بازنویسی نمی‌شود.

```bash
python scripts/pdf_source_kit.py --archive /path/corresponding-source.zip --out /new/source-kit
python -I -S /new/source-kit/licensed-build-files/scripts/pdf_source_kit.py --verify /new/source-kit --expected-manifest-sha256 HASH
python -I -S /new/source-kit/licensed-build-files/scripts/pdf_source_kit.py --verify /new/source-kit --extract-sources /new/preferred-sources
```

پس از تأیید digest مورد اعتماد، از `licensed-build-files` طبق راهنمای داخل بسته
دستور native-only قبلی اجرا می‌شود. ساخت قبلیِ مستقل ۲۰ سورس/۲۱ DLL در
[proof مستقل](../dependencies/pdf-native-rebuild-proof-run.json) ثبت است؛ اسکریپت
native/تنظیماتش در این گام تغییر نکرده و کامپایل ۴۰دقیقه‌ای برای ادعای package
دوباره انجام نشده است.

**محدودیت مهم:** دستور native فعلی ورودی‌های پین‌شده را دانلود می‌کند؛ هنوز خودش
مستقیماً درخت‌های استخراج‌شدهٔ local را مصرف نمی‌کند. استفاده از سورس تغییرکرده
overlay بررسی‌شده می‌خواهد. این بسته SDK آفلاین یا اثبات بازسازی از local-source
نیست و هش مرجع، ممنوعیت تغییر مجاز MIT/LGPL نیست. گیت کامل‌بودن/تحویل recipe
بی‌دلیل بسته نشده است.

## CRT: دامنهٔ آزمون جدا از موتور اصلی

workflow جداگانهٔ `pdf-crt-link-proof.yml` برنامهٔ کوچک C++ با `/MT` می‌سازد؛
directiveهای object، importهای PE، map و log واقعی `/VERBOSE` و مسیر/هش
کتابخانه‌های **جست‌وجوشده** را برای بررسی ثبت می‌کند. جست‌وجوی یک `.lib` اثبات
ورود کد آن به خروجی نیست؛ trace object باید جدا خوانده شود. این probe متعلق به
runner فعلی است، نه link map DLLهای اصلی یا همان ۲۱ DLL بازسازی‌شده.

اجرای [39113097728](https://github.com/Houman-Amiri/VIRA-Accounting-App/actions/runs/39113097728)
روی `0bceb1e` موفق شد: directive صریح `MT_StaticRelease` و `libcpmt/LIBCMT/OLDNAMES`،
هفت مسیر واقعی کتابخانه با اندازه/هش، ۳۱۷ رویداد `Loaded` و import فقط `KERNEL32.dll`
برای **همین probe** ثبت شد؛ نه ۳۱۷ جزء یکتا یا فهرست اجزای موتور. متن کامل log/map
در artifact فقط شواهد، و دو قطعهٔ metadata کامل در
[شواهد probe](../dependencies/pdf-crt-static-probe-evidence.json) و
[پین اجرا/هش‌ها](../dependencies/pdf-crt-static-probe-proof.json) است.

شکست‌های اولیهٔ ثبت شواهد حفظ شدند: `/VERBOSE:LIB` فقط جست‌وجوی library را نشان
می‌داد، نه trace لازمِ object؛ پس به **`/VERBOSE` کامل** تغییر کرد. شرط وجود object
trace حذف/ضعیف نشد و این اصلاح، رفع یک باگ production معرفی نشده است.

با مرجع رسمی Markdown پین‌شدهٔ مایکروسافت، نقش‌ها تفکیک شدند: `libucrt` استاتیک
در SDK، `libvcruntime` پشتیبانی اختصاصی کامپایلر، `LIBCMT` startup استاتیک و
`libcpmt` کتابخانهٔ استاندارد C++ استاتیک. نام‌ها به‌تنهایی انتخاب مجوز نیستند.
**تغییر ساده به `/MD` هم همهٔ کد startup استاتیک را حذف نمی‌کند**؛ مرز allocator/
state بین DLLها نیز باید بررسی شود. هش bytes واقعی این مرجع Markdown از API
پین‌شده موجود است؛ هش DOCXهای قبلی همچنان اختراع نشده است.

حقوق واقعی تولیدکننده و تطبیق اجزای استاتیک DLLهای اصلی همچنان باز می‌مانند؛
SDK/VS نصب‌شده یا موفقیت این probe مجوز بازتوزیع نیست.

## تست، دامنه و توقف

۳۰ تست جدید برای امنیت/قرارداد بسته به تست‌های قبلی اضافه شد؛ **۵۰۶ تست بک‌اند
محلی**، Ruff، Mypy روی ۸۴ فایل و Bandit برنامه/ابزار بسته موفق‌اند. تست‌های
مصنوعی جای بررسی source ZIP واقعی در CI را نگرفته‌اند. نتیجهٔ رگرسیون کامل
ویندوز/فرانت‌اند/مرورگر جدا ثبت می‌شود؛ تست شکست‌خورده پنهان یا ضعیف نمی‌شود.

هر دو سند master، برنامهٔ کار و changelog با این مرحله همگام می‌شوند.
گیت‌های بررسی حقوقی اجزا/CRT، recipe/local-source و تحویل واقعی، LGPL/EULA و
bootstrap/native update/rollback و پذیرش نصب‌شده بازند. هیچ tag/release/version،
اتصال DLL به payload عادی یا تغییری در دادهٔ کاربر و محاسبات مالی نداریم. آزمون
کسب‌وکار روی نصب مالک طبق دستور قبلی به بعد موکول است، نه تأییدشده فرض شده است.
