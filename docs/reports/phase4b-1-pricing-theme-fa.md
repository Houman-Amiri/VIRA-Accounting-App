# گزارش ۴-ب/۱ — جدول قیمت‌گذاری و تم روشن

**دامنه:** موارد ۱ و ۴ از فاز ۴-ب؛ تقویم و اطلاعات پایه هنوز انجام نشده‌اند.
**مجوز:** کاربر پس از نصب ۱.۰.۱۰ اعلام کرد هنوز داده‌ای برای تست ندارد و ادامهٔ
فازها را خواست؛ تست دستی نصب به پایان فازها موکول شد، نه تست خودکار.
**وضعیت:** بخش ۴-ب/۱ پیاده‌سازی شد؛ تست محلی و هر پنج job CI نهایی موفق. انتشار جدید نداریم.

## تغییرات

- ستون‌های سلول و متن نشانی/فرمول از DOM گزارش حذف شدند، نه پنهان با CSS؛ فقط
  شرح ردیف، ساده (تومان) و زنجیردار (تومان) باقی‌اند. توضیح ضرب تیراژ در عنوان
  ردیف تکمیلی نیز از نمایش حذف شد؛ فرمول/نشانی مرجع داخلی عوض نشده است.
- کل سه ردیف جمع تولید سبز، قیمت هر عدد آبی و قیمت نهایی قرمز باقی‌اند.
- زمینهٔ مشترک روشن کرمی و سطح‌های ثانویه سبز بسیار کم‌رنگ شدند؛ متن کم‌رنگ،
  رنگ مثبت/منفی، دکمه‌های اصلی/خطا و مرز ورودی‌ها برای کنتراست تنظیم شدند.
  متن نشان هشدار در تم روشن تیره‌تر شد؛ tokenهای تم تاریک عین ۱.۰.۱۰ باقی‌اند.
- موبایل: ناوبری آیکنی با نام دسترس‌پذیر و فضای بیشتر فرم؛ سه ستون برای مبالغ
  معمول جا می‌گیرند. مبالغ بسیار بلند داخل خود جدول افقی پیمایش می‌شوند، نه کل
  صفحه. ناحیهٔ پیمایش فوکوس‌پذیر است. نشان به‌روزرسانی در موبایل پنهان نمی‌شود.

## شواهد

- پیش از اصلاح، تست جدیدِ قرارداد سه ستون/حذف نشانی‌ها واقعاً با **۵ شکست** قرمز شد؛
  پس از اصلاح سبز است. تست رگرسیون قدیمیِ پنج ستون با نیاز صریح جدید جایگزین شد؛
  تست عددی حذف یا ضعیف نشده است.
- **۱۵۸ تست فرانت‌اند** محلی موفق؛ شامل ۱۵ تست oracle مستقل workbook و ۱۳ تست
  پالت/AA و ثبات همهٔ tokenهای تاریک نسبت به تگ ۱.۰.۱۰. فرمول‌های موتور، workbook،
  fixtures عددی و سیاست literal_sheet تغییر نکردند.
- اعداد تعداد ۱ و ۱۰ و ارقام فارسی، اشتراک کمیسیون، مقدار ناموجود زنجیردار و
  ماندگاری ثابت‌های ذخیره‌شده در تست UI/مرورگر بررسی شدند.
- format، ESLint، TypeScript و build محلی موفق؛ هشدار شناخته‌شدهٔ chunk باقی است.
- Chromium محلی از npm با کتابخانه‌های اجرایی موقت آماده شد؛ خطای آغازینِ
  نبود libnss/libnspr، خطای محیط بود و با فراهم‌کردن کتابخانه‌های بسته رفع شد.
  security برنامه، CORS، auth limiter و منطق API شل نشدند.
- مرورگر واقعی محلی: سناریوی قیمت با عرض‌های ۳۹۰/۱۴۴۰ و هر دو تم؛ سناریوی پوسته
  و کنتراست فرم‌های قیمت، سند، سفارش، تولید، انبار، تنظیمات و واردات بانک؛ و سناریوی
  اعلان به‌روزرسانی در ناوبری موبایل، موفق شدند. همان سناریوها بدون login اضافه
  در مجموعهٔ موجود CI قرار دارند؛ حد امنیتی ورود دست‌کاری نشده است.
- کنتراست متن معمولی/کم‌رنگ روی سطوح مشترک و دکمه‌ها حداقل ۴٫۵:۱، مرز ورودی/focus
  حداقل ۳:۱، و متن جدول/کنترل‌ها با رنگ محاسبه‌شدهٔ مرورگر بررسی می‌شوند؛ ادعای
  اندازه‌گیری همهٔ پیکسل‌ها/نمودارهای کل اپ یا popup بومی Windows نداریم.
- [CI نخستین پیاده‌سازی، پنج job موفق](https://github.com/Houman-Amiri/VIRA-Accounting-App/actions/runs/38967159995).
- [CI کد نهایی `9bffa78`](https://github.com/Houman-Amiri/VIRA-Accounting-App/actions/runs/38968254211):
  **هر پنج job موفق**؛ ۳۰۸ تست بک‌اند، ۱۵۸ تست فرانت‌اند، پنج سناریوی مرورگری،
  قرارداد API و Windows-native شامل ارتقا/بازگردانیِ fixture کد جاری.
  ساخت انتشار عمداً اجرا نشد؛ این شاهد انتشار جدید یا تغییر نصب کاربر نیست.

## داده، انتشار و ادامه

هیچ migration، تغییر backend/API، بازنویسی قیمت تاریخی، تغییر موجودی یا دسترسی به
DB نصب کاربر انجام نشد. نسخه و تگ عمومی همان **۱.۰.۱۰ / `5b47ebb`** است؛ تغییرات
این گزارش در شاخهٔ توسعه‌اند و هنوز روی نصب کاربر قرار نگرفته‌اند.

پیش‌نمایش جدید پورت **۵۱۸۰**، API آزمایشی **۸۸۱۰** و SQLite جداگانهٔ آزمایشی دارد؛
پایگاه از نمونهٔ disposable با SQLite backup API کپی شده، نه کپی خام DB فعال.
ورود نمایشی: `owner` / `e2e-owner-password`. هیچ‌کدام اطلاعات ورود نصب کاربر نیست.

گام بعدی ۴-ب/۲ (تقویم) و سپس ۴-ب/۳ (اطلاعات پایه) است. قبل از migration، حفظ داده
در rollback بین revisionها باید اثبات شود؛ بازگردانی فایل‌های اپ کافی نیست.
آزمون دستی از کاربر اکنون درخواست نمی‌شود و تأییدنشده باقی می‌ماند.
